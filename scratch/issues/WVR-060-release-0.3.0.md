Its copy at `WeaverRuntime.ts:232` (`request: cloneRuntimeJson(request)`) enters `cloneJson` (`packages/core/src/data-model/clone.ts:32-46`), which is iterative and has no cycle check, so it never returns. The process ran out of memory (V8 heap, abort, exit 134) after about 110 seconds. Without an observer the same call returns `SURFACE_NOT_FOUND` at once. So the real failure is a hang and out-of-memory, not a silent drop. The docs now say so, in `docs/debugging.md` (observer section) and in the CHANGELOG Notes, as a known limitation. Typed requests (four strings) are not affected. **Not fixed, because the brief said documentation only.** Proposed fix for the owner: guard the action copy at `WeaverRuntime.ts:232` with the same `isJsonValue` check that `observedValue` uses (a marker when not JSON-safe), and/or add cycle detection to `cloneJson`.
