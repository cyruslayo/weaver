## Context
No cookbook screen mounts the custom catalog. `cookbookCatalog`, DataTable and
BarChart run only in happy-dom tests, and `createBasicWebRuntime` is never given
`additionalCatalogs` by a page. So the real browser has never laid out the
DataTable or the BarChart, and the 360px and keyboard checks have never run on
them. WVR-054 left case (d), the standalone browser check, uncovered for this
reason. WVR-055's custom-catalog recipe also needs a runnable screen to point
at. This issue adds that screen, and nothing else.

## Scope
- One "Orders report" screen in `examples/cookbook`, driven by a deterministic
  agent (no network, no LLM). It runs on the CUSTOM catalog
  (`https://weaver.dev/examples/cookbook/v1`), through
  `createBasicWebRuntime({ additionalCatalogs, additionalRenderers })` with
  `cookbookCatalogRendererRegistrations`.
- Layout: a Column with a heading, a Refresh Button, and two Cards. One Card
  holds a read-only DataTable bound to `/orders` through a data binding. The
  other holds a BarChart bound to `/summary/byStatus` (order value per status)
  through a data binding.
- Refresh is a host-owned action. Its context is the current refresh count
  (a data binding), so a stale or forged count is rejected. The answer is
  `updateDataModel` only, with no `updateComponents`, exactly like the
  dashboard's Refresh.
- The shared harness gets ONE additive optional field on the screen
  definition, `catalog?: { catalog, renderers }`. When it is set, the harness
  passes both to `createBasicWebRuntime` and uses the custom catalog id for the
  surface. Every existing screen stays unchanged.
- The Button renderer and schema are reused from Basic. The custom catalog
  declares `Button` next to `Column`, `Text` and `Card`, and the Button renderer
  is registered under the cookbook id. This is the only change to the custom
  catalog. Its tests that asserted Button was undeclared are updated to match.
- Vite entry `orders-report.html` and `src/entries/orders-report.ts`, a link on
  `index.html`, and a README screen row. The `test` script registers the new
  test file.
- happy-dom tests, and a Playwright spec at both widths.

## Out of scope

**Bugs found in the real browser and fixed**
1. At 360px, Chromium made the DataTable's scroll wrapper a keyboard stop with no role or name. An unlabelled scroll trap is an accessibility gap. The fix is in the renderer. The wrapper is now `role="region"`, `tabindex="0"`, and `aria-label` set to the caption (or "Data table"). This is intentional, so a keyboard user can scroll hidden columns. The tab-order check now expects Refresh, then the named region, at both widths. Renderer test added for the region semantics.
2. Order IDs wrapped onto two lines at 360px. Table cells now use `white-space: nowrap`. The wrapper scrolls, so the page still never widens.
